# ไฟล์ SQL ของระบบ T&T Mansion

รันใน Supabase → SQL Editor ตามลำดับนี้ (ไฟล์ส่วนใหญ่รันซ้ำได้ แต่ดูข้อควรระวังด้านล่าง)

| ลำดับ | ไฟล์ | ทำอะไร | หมายเหตุ |
|---|---|---|---|
| 1 | `01_schema.sql` | สร้างตาราง สิทธิ์ (RLS) ที่เก็บไฟล์ Realtime และห้อง 27 ห้อง | รันก่อนเสมอ |
| 2 | `02_staff_emails.sql` | กำหนดอีเมลผู้ดูแลระบบและเจ้าของกิจการ | **แก้อีเมลเป็นของจริงก่อนรัน** |
| 3 | `05_period_lock.sql` | ล็อกรอบบิลหลังวันที่ 10 ของเดือนถัดไป | ต้องรันหลัง 01 |
| 4 | `07_edit_rules.sql` | ผู้เช่าส่งสลิปใหม่ได้ก่อนอนุมัติ, ล็อกเลขมิเตอร์ก่อนหน้า, ห้ามแก้รายการบิลที่รอตรวจ/ชำระแล้ว | ต้องรันหลัง 01 และ 05 |
| 5 | `08_receipt_and_reject.sql` | เลขใบเสร็จออกโดยฐานข้อมูล + เก็บเหตุผลที่ปฏิเสธสลิป | ต้องรันหลัง 01 |
| ตรวจ | `03_verify.sql` | ตรวจผลหลังติดตั้ง เทียบกับตัวเลขในคอมเมนต์ท้ายบรรทัด | รันเมื่อเสร็จทั้งหมด |

## ข้อควรระวัง
- **ห้ามรัน `01_schema.sql` ซ้ำหลังจากรัน 05, 07, 08 ไปแล้ว** เพราะ 01 มีฟังก์ชันชุดเดิม (เช่น `submit_payment`, `payments_stamp`, `guard_item_lock`) ที่ไฟล์ 05/07/08 แก้ไว้ จะถูกเขียนทับกลับเป็นเวอร์ชันเก่า ถ้าจำเป็นต้องรัน 01 ซ้ำ ให้รัน 05 → 07 → 08 ตามหลังอีกครั้ง
- เลขไฟล์ข้ามจาก 03 ไป 05 และ 05 ไป 07 เพราะไฟล์เดิมที่ไม่ใช้แล้ว (04, 06 และ 05 เวอร์ชันกรองอีเมล) ถูกลบออก
- ไฟล์ SQL ที่มีอยู่ในเครื่อง ไม่ได้เชื่อมกับฐานข้อมูลโดยตรง การลบหรือย้ายไฟล์ไม่กระทบข้อมูลบน Supabase
