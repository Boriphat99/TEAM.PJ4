# ระบบแจ้งเตือนผ่าน LINE (LINE chatbot) — เอกสารออกแบบ

วันที่ 16 พ.ย. 2569 · ขนาดงาน: โปรเจกต์ย่อย (ฐานข้อมูล + Edge Functions 2 ตัว + หน้าเว็บ 2 ส่วน)

## เป้าหมายและเหตุผล
ทำตามวัตถุประสงค์ 2.3 ของโครงร่าง ("เพื่อพัฒนาระบบติดตามทวงถามผู้เช่าที่ค้างชำระค่าบริการ") ข้อ 8 ใน 5.1.2 ตารางที่ 3 ข้อ 6 (ข้อจำกัด) และ 9.1.8
ผู้เช่าได้รับข่าวสารเรื่องบิลทาง LINE โดยไม่ต้องเปิดเว็บ ผู้ดูแลระบบไม่ต้องทักทวงทีละคน

## สิ่งที่ส่ง
| ถึง | เหตุการณ์ | เวลา |
|---|---|---|
| ผู้เช่า | มีใบแจ้งหนี้ใหม่ | ทันทีที่ออกบิล |
| ผู้เช่า | ใกล้ครบกำหนด (บิลยังไม่ชำระ) | วันที่ 3 เวลา 09:00 |
| ผู้เช่า | เลยกำหนดแล้ว เริ่มมีค่าปรับ | วันที่ 6 เวลา 09:00 |
| ผู้เช่า | วันสุดท้ายก่อนผิดนัดชำระ | วันที่ 10 เวลา 09:00 |
| ผู้เช่า | ชำระเงินได้รับการยืนยันแล้ว + ใบเสร็จออกแล้ว (เลขที่ใบเสร็จ) | ทันทีที่ได้เลขที่ใบเสร็จ (ทั้งเงินสดและ QR) |
| ผู้เช่า | สลิปไม่ผ่านการตรวจสอบ + เหตุผล | ทันทีที่ปฏิเสธ |
| ผู้ดูแลระบบ | ผู้เช่าแนบสลิป รอตรวจสอบ | ทันที |
| ผู้เช่า | แอดมินกดส่งเตือนเองจากหน้า "ติดตามหนี้ค้าง" | เมื่อกด |

ข้อความเป็นข้อความธรรมดา บอกห้อง เดือน ยอดเงิน วันครบกำหนด/ค่าปรับ และลิงก์เข้าเว็บ (app_settings.system_url)
เหตุการณ์อัตโนมัติแต่ละแบบส่งครั้งเดียวต่อบิล (บันทึกใน notify_log) ปุ่มส่งเองของแอดมินส่งซ้ำได้

**การตัดสินใจของผู้ออกแบบ:** การอนุมัติสลิปกับการออกใบเสร็จเกิดพร้อมกัน จึงรวมเป็นข้อความเดียวเพื่อประหยัดโควตา

## การเชื่อมบัญชี LINE
- หน้าโปรไฟล์ (ผู้เช่าและผู้ดูแลระบบ) มีการ์ด "เชื่อม LINE": ปุ่มเพิ่มเพื่อน LINE OA ของหอ + ปุ่มขอรหัส 6 หลัก (อายุ 10 นาที)
- ผู้ใช้พิมพ์รหัสส่งในแชท LINE OA → เว็บฮุกจับคู่รหัส → บันทึก LINE userId → บอทตอบกลับ (Reply ไม่นับโควตา)
- ยกเลิกการเชื่อมได้เองจากหน้าโปรไฟล์ เก็บเฉพาะ LINE userId (สอดคล้อง พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล)
- ผู้ที่ไม่ได้เชื่อม LINE ยังดูทุกอย่างในเว็บได้ตามเดิม

## หน้า "ติดตามหนี้ค้าง" (แอดมิน; เจ้าของดูอย่างเดียว)
รายการบิลที่ยังไม่ชำระและเลยกำหนด: ห้อง ผู้เช่า เดือน ยอดค้าง จำนวนวันที่ค้าง สถานะเชื่อม LINE ส่งเตือนล่าสุด ปุ่ม "ส่งเตือน" รายห้อง และ "ส่งเตือนทุกห้องที่เชื่อม LINE"

## แนวทางที่พิจารณา
1. **ฐานข้อมูลเป็นตัวสั่งส่ง (เลือก):** trigger บนตาราง invoices/payments + pg_cron รายวัน → pg_net เรียก Edge Function `line-notify` → LINE Push API ส่งได้แน่นอนแม้ผู้ใช้ปิดเบราว์เซอร์
2. หน้าเว็บเรียก Edge Function หลังกดปุ่ม: ง่ายกว่า แต่ข้อความหลุดถ้าปิดหน้าเว็บกลางทาง และการเตือนตามวันทำไม่ได้ — ไม่เลือก
3. LINE Notify: ปิดบริการแล้ว — ใช้ไม่ได้

## ส่วนประกอบ
- ตาราง `line_links(user_id pk, line_user_id unique, linked_at)`, `line_link_codes(code pk, user_id, expires_at)`, `notify_log(id, invoice_id, payment_id, kind, to_user, ok, error, sent_at)`; RLS: ผู้ใช้เห็น/ลบเฉพาะของตน แอดมินอ่านได้ทั้งหมด
- RPC `line_link_code()` สร้างรหัส, `line_unlink()`, `line_remind(invoice_id)` (แอดมิน)
- Edge Function `line-webhook` (verify_jwt=false, ตรวจลายเซ็น X-Line-Signature ด้วย LINE_CHANNEL_SECRET)
- Edge Function `line-notify` (เรียกได้เฉพาะด้วย secret ภายในจาก vault) ส่ง Push ด้วย LINE_CHANNEL_ACCESS_TOKEN
- pg_cron ทุกวัน 02:00 UTC (09:00 น.) ตรวจบิลค้างตามวันที่ 3/6/10
- secret ทั้งสองตัวผู้ใช้ใส่เองใน Supabase → Edge Functions → Secrets

## ไม่ทำ (non-goals)
- ไม่เปลี่ยนกฎค่าปรับ/สถานะบิลเดิม · ไม่แตะระบบอีเมล Resend · ไม่ทำ Rich menu / Flex message · ไม่ส่งข้อความหาเจ้าของ

## ข้อจำกัด
- แพ็กเกจฟรี LINE OA ไทย 300 ข้อความ/เดือน (กรณีมากสุดประมาณ 160)
- ส่งได้เฉพาะผู้ที่เพิ่มเพื่อนและเชื่อมบัญชีแล้ว
